Trino 网关（Java）— 架构与查询生命周期
示意结构：协议端点 + 认证 + SQL 校验规则引擎 + 流量治理 + 路由转发，经标准 Trino REST 协议连接客户端与 Trino 集群
① 架构总览
② 查询生命周期（POST 提交 → 轮询取数 → 结束）
③ 模块清单与职责
网关核心链路
gateway-protocol：/v1/statement 端点、QueryResults 编解码、nextUri 重写、查询映射
gateway-auth：LDAP/JWT/Kerberos/mTLS/可信头认证、身份传播
gateway-sql：trino-parser 解析、语句分类、AST 特征提取
gateway-rules：规则引擎、文件/DB/脚本/SPI 动态加载、Admin API
gateway-flow：限流（每分钟 SQL 数）、排队（容量/超时）、并发控制
gateway-routing：集群注册、健康检查（INFO_API/METRICS）、路由策略
gateway-proxy：后端 TrinoClient 转发、取消、空闲自动终止
支撑与管理
gateway-store：MySQL/PG + Flyway；规则、限流策略、查询历史（SQL 脱敏）、HA 状态
gateway-admin：规则 CRUD/dry-run/回滚、限流热更新、查询 kill
gateway-observability：Prometheus 指标、结构化审计、traceToken 透传
gateway-config：YAML + 环境变量，热更新
gateway-server：Jetty 异步 HTTP、TLS 终止、过滤器链
gateway-app：启动装配（JAR / Docker / Helm）
关键语义（协议兼容）
校验拒绝 → HTTP 200 + QueryResults.error（DBeaver 显示清晰 SQL 错误）
限流/排队 → HTTP 429 + Retry-After（客户端自动重试）
nextUri 缺失 = 查询结束；首请求头记忆、轮询不带头
Set-Session / Started-Transaction / Added-Prepare 响应头必须透传
元数据语句（SHOW/DESCRIBE/information_schema）默认放行
